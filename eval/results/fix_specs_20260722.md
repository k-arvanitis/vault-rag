
6. Print a per-file summary: repaired / still-empty / skipped counts.
7. The script must be idempotent (re-running it finds 0 polluted chunks and exits cleanly)

## TASK 4 — Excel FORMAT-step extractive verification (F3)

**Problem.** In `src/tools/excel.py`, the `evaluate` node's FORMAT LLM call
(gpt-4o-mini + `FORMAT_PROMPT`) is extractive by contract (rule 5: copy values verbatim) but
was caught live outputting `"150.00"` from an input containing only
`Purchase of Expenditure: MATERIALS` — a fabricated number, ~1/3 of runs. All upstream gates
were correct; this is the last unguarded step.

**Change 1** — add to `src/tools/excel.py` (module level, near `_execute_sql`):

```python
def _answer_in_result(answer: str, result_text: str) -> bool:
    """True when every value in a formatted answer appears in the SQL result text.

    The FORMAT step is copy-only by contract (FORMAT_PROMPT rule 5), so any
    output value absent from the result rows is a fabrication. Numeric values
    compare float-equal so "150.0" in the rows matches "150.00" in the answer;
    text values compare case- and whitespace-insensitively.
    """
    norm_result = re.sub(r"\s+", " ", result_text).lower()
    result_nums: set[float] = set()
    for tok in re.findall(r"-?\d[\d,]*\.?\d*", result_text):
        try:
            result_nums.add(float(tok.replace(",", "")))
        except ValueError:
            pass
    for part in answer.split(";"):
        value = part.split("=", 1)[-1].strip()
        if not value:
            continue
        try:
            if float(value.replace(",", "")) in result_nums:
                continue
        except ValueError:
            pass
        if re.sub(r"\s+", " ", value).lower() in norm_result:
            continue
        return False
    return True
```

## TASK 7 — Judge: treat equivalent date formats as exact matches (F8)

**Problem.** `doc_007_published_spend_report_april_25_qa__qa_2`: predicted `2025-04-29`,
gold `29/04/2025` — same date, scored wrong. Ingestion normalizes all spreadsheet dates to
ISO (`_normalize_dates` in `src/duckdb_store.py`), so the SQL path can never emit the
source's original format; this must be fixed in scoring, not the pipeline.

**Change** — in `eval/run_eval.py`, locate the exact-match shortcircuit in the judging phase
(grep `exact_match`). Add a helper next to it:

```python
_DATE_FORMATS = ("%Y-%m-%d", "%d/%m/%Y", "%m/%d/%Y", "%B %d, %Y", "%B %d %Y", "%d %B %Y")


def _as_date(text: str):
    """Parse a lone date string in any corpus-seen format; None if not a date."""
    from datetime import datetime

    cleaned = text.strip().rstrip(".")
    for fmt in _DATE_FORMATS:
        try:
            return datetime.strptime(cleaned, fmt).date()
        except ValueError:
            continue
    return None
```

In the exact-match comparison, before falling through to the LLM judge: if
`_as_date(gold) is not None and _as_date(gold) == _as_date(predicted_value)` → treat as
exact match. Apply it only when the GOLD answer parses as a lone date (don't date-scan long
prose answers). If the predicted answer is a sentence, also try the first
`\d{4}-\d{2}-\d{2}|\d{1,2}/\d{1,2}/\d{4}` token from it.

**Ambiguity warning:** `%d/%m/%Y` before `%m/%d/%Y` in `_DATE_FORMATS` is deliberate — the
corpus is UK data (dayfirst), matching `_normalize_dates`' `dayfirst=True`. Keep that order.

**Tests:** if `eval/` has no tests, add `tests/test_eval_dates.py` importing `_as_date` and
